## 1. 知乎 —— 回答问题，不是发文章

**打法**：找到真实的、已有点赞数的问题，在**问题下回答**。知乎不给「发文章」引流，只给「好回答」引流。

### 优先回答的三个问题类型

搜这几个关键词找有流量的问题：
- 「麦当劳怎么点最划算」
- 「麦金卡/麦咖啡卡值得买吗」
- 「减脂期能不能吃麦当劳」

### 回答模板 A：问「麦金卡值不值得买」

```
先说结论：值不值得，取决于你每次点的是不是「带卡价」的那些商品，而不是你一年吃几次。

我扒了一家门店的完整菜单（122 个在售餐品），其中 14 个带「麦金卡价」，
平均折扣 49%，最高一项从 ¥114.5 降到 ¥49.9，省 ¥64.6。

所以判断方法应该是：
    你每次平均能省多少 × 次数  >  卡费 ？

这家店的中位数是每次省 ¥26.5。也就是说，只要你的卡费低于 ¥26.5，一次就回本。

官方没有公开卡费的查询接口，所以我做了个小工具反推：
它不猜「值不值」，而是给你一个「盈亏平衡卡费」——
低于这个数你这一单就回本，高于这个数你得算多少次。

（这是麦当劳程序员创意开发大赛的参赛作品，非官方）
工具：https://monekey.github.io/mcd-meal-optimizer/
```

**这条回答的价值点**：结论先行、数据可核验、给判断方法而不是推销。

### 回答模板 B：问「麦当劳怎么点最省钱」

```
先给结论：单点和点套餐差价可以很大。我实测同一家门店：

    巨无霸 + 中薯条 + 中杯可乐，单点 ¥48.50
    直接点「巨无霸三件套」，¥33.50，内容一模一样，省 ¥15

但这里有个坑，也是我做这个工具时最想提醒的：
**「省得多」不等于「省」**。如果工具建议把一个四件套换成单品汉堡，
看着省了十几块，实际是少了薯条和饮料——那是少买，不是省钱。

所以我给工具加了一条硬规则：只做「内容不变少」的替换
（套餐只换套餐、单品只换单品、新套餐的组成必须覆盖原套餐），
另外支持把多个单品打包成一个套餐。

顺手还算了热量：官方营养接口只覆盖了 43% 的在售餐品，套餐一个都没给，
我用套餐的默认组成把它补到了 71%。

（参赛作品，非官方）
代码：https://github.com/Monekey/mcd-meal-optimizer
```

## 2. 即刻 —— 200 字以内，独立开发者圈

**打法**：即刻氛围最松，**短 + 直接 + 带链接**，别写长文。可以带 #独立开发 话题。

```
参加麦当劳黑客松做了个省钱点餐器。

你说想吃什么，它枚举 3468 个真实组合，用官方接口核价，
给「最省 / 最平衡 / 更轻」三套方案，每套带价格和热量。

顺手算了个麦金卡回本点：这家店 14 个商品带卡价，平均能省 49%，
最高一项 ¥114.5 → ¥49.9。

外送和到店是两套价（巨无霸 ¥25.5 vs ¥28.5），也分开算了。

内置真实门店快照，不用 Token 也能玩：
https://monekey.github.io/mcd-meal-optimizer/

非官方，欢迎喷
```

**技巧**：即刻可以连发 2–3 条（一条讲数据、一条讲坑、一条给链接），比一条长文转化好。

## 3. CSDN —— SEO 流量池，标题可以更直白

**打法**：CSDN 的读者是来**找解决方案**的，标题要带明确问题词。同一篇技术长文，改标题和小标题即可复用。

**标题候选**：
- `麦当劳 MCP 接入实战：5 个文档没写的坑，以及「数值不进 LLM」的架构选择`
- `用麦当劳 MCP 做了个点餐优化器：价格和热量一起算，实测省了一半`

**建议结构**（复用 `release/掘金长文.md` 的技术主体）：
1. 开篇：为什么做（省多少钱的数字先给）
2. 接口层的 5 个坑（`code` vs `productCode` 静默返回 0 这条最值钱，搜索引擎会有人搜）
3. 「数值不进 LLM」的架构取舍
4. 套餐营养补全：43% → 71%
5. 「省 ≠ 少买」的三条铁律
6. 麦金卡 ROI 的盈亏平衡卡费
7. 链接

**CSDN 特有注意**：
- 代码块要标语言
- 一定要放外链（CSDN 是今天这几个平台里**最愿意给外链权重**的）
- 标签加：`#MCP` `#大模型应用` `#Node.js` `#外卖`

## 4. 腾讯云开发者社区 / 阿里云开发者社区 —— 长尾 SEO

这两个站点**能直接发文章、无需邀请码**，而且**搜索长尾很强**（技术类问题在百度/Google 上会被索引到）。

**打法**：和掘金那篇基本同源，但标题要更「问题导向」，因为这些站点的读者是带着问题来搜解决方案的。

标题建议：
- `接入第三方 MCP 的通用坑：字段名不一致会静默失败，返回值不是纯 JSON`

> 泛化到「MCP 接入通用经验」反而更容易在这些平台被搜到 —— 因为读的人不关心麦当劳。

## 5. 不建议做的

| 平台 | 原因 |
|---|---|
| V2EX | 需要邀请码 |
| 少数派 | 投稿需人工审核，来不及 |
| 微信公众号 | 需认证/订阅号，冷启动极慢 |
| 小红书 | 转化率是开发者社区的 1/6，且「站外导流」是最高优先级红线 |
| B 站/抖音 | 要做视频，制作成本高（建议第 10 天后再说） |
| WorkBuddy 技能市场 | 不是内容平台，是**上架渠道**，要实名认证，价值更高，优先做 |

## 6. 执行顺序（按「投入产出比」排）

1. **知乎**（3 个回答）—— 长尾最久，且最容易在搜索里被持续点击
2. **即刻**（2 条）—— 圈内传播快，容易被同行转发
3. **CSDN**（1 篇）—— SEO 流量池，标题带问题词
4. **腾讯云开发者社区**（1 篇）—— 泛化的 MCP 接入经验，长尾
5. 每发完一个，**把链接回填到仓库 README 的「在哪里被讨论过」** —— 这本身也是给 GitHub 访客的信任信号

## 7. 通用注意事项

- **每个平台都要如实标注「非官方 / 参赛作品」** —— 赛事规则明确要求
- **不要在同一平台重复发相同内容**（会被折叠）
- 发完把链接记到 `release/发布物料包.md`，避免重复发
- **不要在任何平台放 MCP Token 或真实手机号/地址**
