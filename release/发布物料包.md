## 1. 掘金 / CSDN 技术长文

**标题**：麦当劳 MCP 有 35 个工具，官方文档只写了 33 个

**开头**：

```
最近参加麦当劳的程序员创意开发大赛，基于官方 MCP 做了个省钱点餐器。
接的过程中发现官方文档和实际接口有几处对不上，记一下，给后来者省点时间。

一、工具数是 35，不是 33

tools/list 实测返回 35 个，比 README 列的多两个：
- query-promotions（团餐满减规则，注意：仅企业团餐 beType=6 可用）
- query-survey-coupon（按订单号查 CSAT 满意度奖券）

二、query-meals 的 code 不等于 calculate-price 的 productCode

传错不会报错，会静默返回 price: 0 和空 productList。
我在这上面浪费了半天。
```

**正文要点**（每条都是真踩过的）：

1. **价格单位不统一**：`query-meals` 返「元」字符串（`"33.5"`），`calculate-price` 返「整数分」（`4850`）
2. **返回是混合体**：每个响应都是「Markdown 说明 + `## Original Response` 里的原始 JSON」，
   而 `query-store-coupons` 这类**只有 Markdown 表格，没有 JSON 行**
3. **转义换行**：`list-nutrition-foods` 把 160 行塞在一个字符串里，行分隔是**字面量 `\n`**，
   直接 `split('\n')` 会解析失败
4. **下单有隐藏必填项**：`create-order` 必传 `takeWayCode`，取值来自 `calculate-price` 返回的 `takeWayList[].code`
5. **返回会抖动**：实测同一 session 连续 5 次调用 `list-nutrition-foods` 全部返回空文本，必须做重试
6. **空关键词查不到门店**：`searchType=2` + 空 `keyword` 返回空数组，需要兜底

**架构选择**：

```
MCP 只负责取真实数据（菜单/券/价格/营养）
本地确定性算法负责全部算术（整数分，无浮点）
LLM 只负责理解意图 + 讲解方案
```

我们叫它「数值不进 LLM」。好处是每个方案都可复现、可解释、可回归测试——仓库里 27 项断言，`npm test` 一键跑。

**结尾**：附 demo 链接 + 仓库链接。

