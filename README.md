# 麦麦点餐官 · McOrder

> **麦当劳官方 App 没告诉你的事：你这一单还能再省多少钱、少吃多少热量。**
>
> 基于**麦当劳中国官方 MCP** 的价格 × 热量双目标点餐优化器 —— 并附一个**麦金卡 ROI 精算器**。

## 一句话介绍

在麦当劳点餐，真正的难题不是"想吃什么"，而是：

- 同样的东西，**用券、换套餐、买不买麦金卡**，差价可能有三分之一；
- 想吃轻一点，但**没人告诉你这一单到底多少大卡**；
- 官方 App 只会展示商品，**不会帮你算组合**。

**麦麦点餐官把"点餐"变成一个可计算的问题：** 你说想吃什么品类，它枚举全部可行组合，用官方核价确认，给你三条路线 —— **最省 / 最平衡 / 更轻**，每一条都带实付金额、总热量和逐项拆解。

## 扒完一家门店的菜单后，发现了三件事

下面每个数字都是从麦当劳官方 MCP 实时拉下来的真实数据（北京建外SOHO A座餐厅，122 个在售餐品，快照于 2026-10-10），**没有一个是我编的**：

| 发现 | 数据 |
|---|---|
| **麦金卡平均能省 49%** | 15 个商品带麦金卡价，最高一项从 ¥114.50 降到 ¥49.90（省 ¥64.60） |
| **同一份东西，差价能到 3 倍** | 巨无霸 + 中薯条 + 中可乐：**单点 ¥48.50，套餐 ¥33.50** |
| **官方营养接口只覆盖 43% 的在售餐品** | 122 个 SKU 里只有 53 个能直接匹配到热量 —— **所有套餐的热量，官方都没给**。我把它补到 **87 个（71%）** |

第三条是这个项目存在的技术原因：套餐热量只能靠 `query-meal-detail` 拿到默认组成，
再把各组件相加。不做这一步，"热量约束"就是假的。

## 它和别的"省钱脚本"有什么不同

| 能力 | 常见省钱工具 | 营养类工具 | **麦麦点餐官** |
|---|:--:|:--:|:--:|
| 组合最优（只看钱） | ✅ | ❌ | ✅ |
| 热量/营养约束 | ❌ | ✅ | ✅ |
| **价格 × 热量放同一个目标函数** | ❌ | ❌ | ✅ |
| **麦金卡 ROI / 盈亏平衡卡费** | ❌ | ❌ | ✅ |
| **购物车实时"还能再省多少"** | ❌ | ❌ | ✅ |
| 复刻官方点餐动线（不改使用习惯） | ❌ | ❌ | ✅ |
| 多份点餐档案（预算/热量/忌口） | ❌ | 部分 | ✅ |

### 三个具体的技术主张

**① 数值不进 LLM。**
所有算术在本地用「整数分」完成，没有浮点误差；大模型只负责理解意图和把结果讲成人话。因此每个方案都是**可复现、可解释、可回归测试**的 —— 仓库内置 27 项断言测试，`npm test` 一键验证。

**② 数据缺失不当成 0。**
`list-nutrition-foods` 只覆盖单品，套餐对不上（122 个 SKU 里只有 53 个能直接匹配到热量）。
我们调用 `query-meal-detail` 拿到套餐默认组成，把各组件的营养相加（结果落盘缓存，第二次起零调用）。
**仍然未知的，如实标注「热量待核实」，并且不允许用它去"满足"热量上限。**

**③ 只给"内容不变少"的省钱建议。**
把「安格斯厚牛堡四件套 ¥37」换成「巨无霸 ¥25.5」看着省 ¥11.5，实际少了薯条和饮料 —— 那不是省钱，是少买。
所以替换建议有三条铁律：**套餐只换套餐、单品只换单品、套餐的新组成必须覆盖原组成**。
真正的大头是另一类建议：**把多个单品打包成套餐**（单点 ¥48.50 → 套餐 ¥33.50）。

**④ 不依赖未知量给结论。**
麦金卡的卡费 MCP 查不到 —— 所以我们不去猜"值不值"，而是输出**「盈亏平衡卡费」**：*只要卡费低于 ¥26.50，你这一单就已经回本。* 这是一个不需要任何假设、可以直接验证的结论。

## 安装与运行

### 前置条件

- Node.js ≥ 18（无第三方依赖，零 npm install）
- 一个麦当劳 MCP Token

### 1. 申请 MCP Token

前往 https://open.mcd.cn/mcp ，手机号登录 → 右上角「控制台」→ 激活 → 复制 Token。

### 2. 配置 MCP 连接

在 WorkBuddy 左侧边栏【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置 MCP】，填入 [`mcp-config.example.json`](mcp-config.example.json) 的内容，把 `${MCD_MCP_TOKEN}` 换成你的真实 Token，保存后【启用】。

也可以只在运行服务时用环境变量注入：

```bash
export MCD_MCP_TOKEN="你的Token"
```

> ⚠️ 仓库中永远不放真实 Token。`.gitignore` 已排除 `.env` 与 `mcp-config.json`。

### 3. 启动

```bash
git clone <本仓库>
cd mcd-meal-optimizer
npm start          # 等价于 node server/index.mjs
```

打开 **http://127.0.0.1:8791**

> ⚠️ 必须用后端自己的地址打开。用 `file://` 双击打开会因为取不到 `/api` 而空白 —— 麦当劳 MCP 是 Streamable HTTP，浏览器不能直连，必须经过本地服务代理。

### 4. 跑测试（不需要 Token）

```bash
npm test
```

## 使用示例

### 网页端

1. 打开 http://127.0.0.1:8791 ，自动定位到最近门店
2. 左侧选分类（巨无霸/牛鱼肉堡、饮品、小食甜品…），点 `＋` 加购
3. 底部会实时出现 **「同样内容还能再省 ¥11.50」**，点开可以看到每一处可替换项和三条重排路线
4. 点「去结算」→ 官方 `calculate-price` 核价 → 确认下单，返回官方支付链接

### 命令行 / API

```bash
# 查门店
curl "http://127.0.0.1:8791/api/stores?mode=takein&city=北京&keyword=国贸"

# 拉菜单（首次会补全套餐营养）
curl "http://127.0.0.1:8791/api/menu?storeCode=1950564&mode=takein"

# 组合优化
curl -X POST http://127.0.0.1:8791/api/solve -H 'Content-Type: application/json' -d '{
  "storeCode":"1950564","mode":"takein",
  "wants":[{"label":"汉堡","category":"巨无霸 牛鱼肉堡","qty":1},
           {"label":"饮料","category":"饮品","qty":1}],
  "constraints":{"budgetFen":4500,"maxKcal":700}
}'

# 麦金卡 ROI
curl "http://127.0.0.1:8791/api/card-roi?storeCode=1950564&visits=8&feeFen=1900"
```

## 设计取舍

- **不做多 Token 托管**：MCP Token 绑定真实会员身份，替他人持有凭证有合规风险。因此"多人"被实现为**同一账户下的多份点餐档案**。
- **不接第三方团购券**：实测 MCP 的满减规则查询（`query-promotions`）**仅对企业团餐（`beType=6`）开放**，个人点餐场景无法获取，抖音/美团团购券不在能力范围内。宁可少一个宣传点，不做假功能。
- **不代付**：订单创建后只返回官方支付链接，付款始终在麦当劳官方渠道完成。
- **不用大模型做算术**：见上文"三个技术主张"。

---

## 已知边界

- 套餐营养依赖 `query-meal-detail` 的默认组成；用户自定义特制后的营养会有偏差。
- 券的叠加规则复杂（满减/买赠/第二份半价），目前只有**固定价券**会自动参与组合优化，其余类型仅展示与提示，最终以 `calculate-price` 核价为准。
- 麦金卡卡费需要用户自行填写。
- 部分门店可能因为菜单接口波动导致某次加载失败，界面会给出可重试的提示。
