# 常见问答与排错

## 报错：「未找到麦当劳 MCP Token」

去 <https://open.mcd.cn/mcp> 用手机号登录 → 右上角【控制台】→【激活】→ 复制 Token。

拿到后二选一：

1. 环境变量：`export MCD_MCP_TOKEN="你的Token"`
2. 在 WorkBuddy 的【连接器】页启用 `mcd-mcp`（本 Skill 会从 `~/.workbuddy/mcp.json` 自动读取）

**不要把 Token 写进任何仓库文件。**

## 报错：`query-meals 调用失败`

1. 确认 `storeCode` 是真的 —— 先用 `node cli.mjs stores --city 北京` 查一个。
2. 确认门店在营业时间外也可能返回空菜单，换个时间试。
3. MCP 偶发返回空，CLI 已内置重试；如果仍失败，等 10 秒再试一次。

## 核价返回 `¥0.00`

**这是字段映射问题的典型症状**，不是商品不可售。
请检查传给 `calculate-price` 的是不是 `productCode`（而不是 `code`）。

## 「热量待核实」是什么意思

说明这个商品的营养数据在官方接口里查不到（套餐尤其常见，即使做过组成补全仍可能缺失）。

**不要把它当成 0 kcal。** 在回答用户时要如实说明：
「其中 N 项热量待核实」，并且不能说这一单"满足了 ≤X kcal 的约束"。

## 「还能再省」的建议，怎么判断是不是"少买"？

三条铁律：

1. **只做同类替换**：套餐只换套餐，单品只换单品
2. **套餐内容不能变少**：新套餐的组成必须**覆盖**旧套餐的组成
3. 支持「打包」方向：把购物车里多个**单品**打包成**套餐**

反例：把「安格斯厚牛堡四件套 ¥37」换成「巨无霸 ¥25.5」，看着省 ¥11.5，
实际少了薯条和饮料 —— **那是少买，不是省钱**。这类建议必须过滤掉。

## 为什么不能只给"最便宜的那个"

因为价格不是唯一目标。用户可能同时在控热量、控预算、要够蛋白。
本 Skill 输出三条路线（最省 / 最平衡 / 更轻），让用户自己选，而不是替他决定。

## 支持麦乐送（外送）吗

支持，加 `--mode delivery --address <地址ID>`。

**注意这不是"换个参数"那么简单**：外送与到店的**菜单和价格是两套**。
实测同一家门店的「巨无霸」：到店 ¥25.5，麦乐送 **¥28.5**。
所以不要把到店的价格套到外送问题上。

外送还多了两步前置：
1. `delivery-query-addresses` 拿收货地址（⚠️ 工具名是**复数** addresses；
   文档里提到的 `delivery-query-address` 单数形式**不存在**，调用会返回 `unknown tool`）
2. `delivery-query-stores` 用地址查可配送门店，拿到 `storeCode` + **`beCode`**

`beCode` 是外送核价与下单的**必传参数**，到店场景则不需要。CLI 已封装，给 `--address` 即可。

## 能帮用户下单吗

**能，但必须由用户明确确认。** 走 `order` 命令：

```bash
# 第 1 步：预演（不会创建订单）
node cli.mjs order --store 1950564 --cart "1100:1" --take-way eat-in

# 第 2 步：把清单/金额复述给用户，等他明确同意

# 第 3 步：才加 --confirm
node cli.mjs order --store 1950564 --cart "1100:1" --take-way eat-in --confirm
```

- **不带 `--confirm` 一定不会创建订单**，这是硬保证
- 到店下单必须带 `--take-way`（选项来自核价返回的 `takeWayList`，通常是 堂食 / 外带）；
  没给且选项不止一个时，命令会拒绝执行并把选项列出来
- 外送下单不传 `takeWayCode`，但必须传 `addressId`
- **不涉及支付** —— 订单创建后是「未支付」状态，要去麦当劳官方 App / 小程序付款

## 为什么下单前一定要先核价

两个原因：

1. `takeWayCode` 的**唯一来源**就是 `calculate-price` 返回的 `takeWayList`，
   不核价就没有合法的取餐方式可传
2. 菜单价 ≠ 实付价。优惠、配送费都在核价里体现（实测同一单：商品价 ¥15.50，实付 ¥21.50）

## 门店/外卖的价格会变吗

会。这是实时数据，而且**菜单本身也会变**（实测同门店从 114 个 SKU 变成 122 个）。
所以：不要缓存太久、不要把某次查询的价格当成"标准答案"，过期了就重新拉。
