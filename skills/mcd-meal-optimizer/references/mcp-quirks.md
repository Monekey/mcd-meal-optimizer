# 麦当劳 MCP 接入细节与踩坑

本文是实测总结，用于减少重复踩坑。所有结论都来自真实调用。

端点：`https://mcp.mcd.cn`　协议：`2025-06-18`　限流：600 次/分钟
返回形态：SSE（`text/event-stream`），需要逐块读。

---

## 1. 工具数量与文档不一致

`tools/list` 实际返回 **35** 个工具，官方文档列出 **33** 个。

多出来的两个：

| 工具 | 说明 |
|---|---|
| `query-promotions` | ⚠️ **仅企业团餐 `beType=6` 可用**，个人点餐场景用不了 |
| `query-survey-coupon` | 问卷券 |

> 如果你的方案依赖「满减券智能组合」，请注意 `query-promotions` 走不通。
> 个人开发者能拿到的是：麦麦省可领 / 我的券 / 门店券 / 一键领 / CSAT 奖券，共 5 类。

---

## 2. ⚠️ 最容易踩的坑：`code` → `productCode`

**这是最危险的一个，因为它静默失败。**

| 工具 | 字段名 |
|---|---|
| `query-meals` 返回 | `code` |
| `calculate-price` 入参 | `productCode`（`items[].productCode`） |

它们是同一个值，但**字段名不同**。传错或传漏的后果：

```
HTTP 200，没有 error 字段，没有 warning，返回 price: 0
```

你会以为「这个商品不可售」，实际上只是字段名不对。

**防御措施**：核价返回 `price === 0` 且 `productList` 非空时，判为**字段映射错误**，而不是"不可售"。

---

## 3. 返回不是纯 JSON，而是「Markdown + 内嵌 JSON」

所有工具的返回都是这种混合体：

```
# 查询附近门店

## 请求参数
...

## 返回
{"success":true,"code":0,"data":[...]}
```

**必须写解析层。** 注意不要用「取第一行像 JSON 的」这种策略 —— 说明文档里也会出现 JSON 示例。
正确做法是从 `{"success"` 的位置开始，用支持流式的解码器自己找边界：

```js
const i = text.indexOf('{"success"');
const [obj] = new JSONDecoder().raw_decode(text.slice(i));
return obj.data;
```

---

## 4. 营养表用「字面量 \n」分隔

`list-nutrition-foods` 返回的不是数组，而是自定义格式：

```
[160]{productName,energyKcal,protein,fat,carbohydrate,sodium,calcium}:巨无霸,513,27,28,44,1010,190\n中杯可乐,150,0,0,38,15,5\n...
```

**那个 `\n` 在字符串里是字面的反斜杠加 n，不是真换行。**

所以 `split('\n')` 拿不到东西，必须先 `replace(/\\n/g, '\n')`。

---

## 5. 价格是整数「分」

`calculate-price` 返回 `4850` = ¥48.50。

**这是好事** —— 全链路用整数分做算术，天生没有浮点误差。
建议客户端也坚持整数分，只在展示层转成元。

---

## 6. 下单必传 `takeWayCode`

取值来自核价返回的 `takeWayList`（堂食 / 外带）。不传会失败。
所以下单前**必须先核价一次**拿到 `takeWayList`。

---

## 7. `list-nutrition-foods` 返回不稳定

实测：首次调用正常，之后**连续 5 次调用全部返回空**。
没有报错，没有 HTTP 错误码，就是空字符串。

**必须做**：重试（带退避）+ 本地快照兜底。不要假设一次调用就能拿到。

---

## 8. 套餐营养要靠 `query-meal-detail` 补

`list-nutrition-foods` 只覆盖单品。实测门店 122 个在售 SKU 里**只有 53 个（43%）**能直接匹配到热量，**所有套餐都没给**。

但 `query-meal-detail` 会返回套餐的**默认组成**，例如：

```
安格斯厚牛堡四件套随心选
  ├─ 安格斯厚牛堡 ×1
  ├─ 中薯条 ×1
  ├─ 中杯可乐 ×1
  └─ 麦辣鸡翅 ×2
```

把各组件的热量相加即可补全。结果建议落盘缓存，第二次起零调用。

> ⚠️ 仍然未知的，**如实标注「热量待核实」，并且不允许用它去"满足"热量上限**。
> 早期版本把未知热量当成 0，结果「0 kcal 套餐」在所有低卡排序里都排第一 ——
> 这是用数据缺失伪造达标，比算错更危险。

---

## 9. 麦金卡价的识别

菜单里带 `discountType: "麦金卡优惠"` 的商品就是麦金卡价商品，同时会给 `originalPrice` 与 `currentPrice`。

实测门店 122 个 SKU 中 **14 个**带卡价，价差最大的一项：¥114.5 → ¥49.9（省 ¥64.6）。

**卡费本身 MCP 查不到。** 所以不要猜"值不值"，而是算**盈亏平衡卡费**：
只要卡费低于这个数，当前这一单就已经回本。这是一个不需要假设、可以直接验证的结论。

---

## 10. 门店查询的行为

`query-nearby-stores` 用 `searchType=2` + 空 `keyword` 可能返回空数组。
建议按顺序兜底：关键词 → 收藏餐厅 → 用城市名当关键词 → 用「麦当劳」当关键词。

`delivery-query-stores`（麦乐送）参数不同，需要 `addressId`。
