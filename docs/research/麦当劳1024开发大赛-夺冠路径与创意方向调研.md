## 2. ★ 最重要洞察：这是「Star 竞速」，不是评审制

### 2.1 规则原文依据（三条，决定全部打法）

> ① 「对符合要求的参赛项目，麦当劳按照其在 **GitHub 平台获得的公开 Star 数量** 进行排名。」
>
> ② 「**Star 数为 0 的项目不进入排行榜**，如最终仅有 80 个项目 Star > 0，则仅该 80 个项目进入排行榜。」
>
> ③ 「最终排名以截至北京时间 2026-10-26 00:00 **项目累计获得的公开 Star 总数** 为依据，**活动开始前已获得的 Star 亦计入**。」

### 2.2 由此推出的 5 条战术结论

| # | 结论 | 说明 |
|---|---|---|
| 1 | **"技术评审"只存在于资格门槛层面**（真实用 MCP、文件齐全、内容合规），不影响名次 | 不要花 80% 时间做架构，要留 50% 时间做传播 |
| 2 | **发布越早越好** | Star 可累计 16 天，早 1 天就多 1 天曝光 |
| 3 | **仓库创建时间必须在 2025-12-25 00:00 之后** | 老旧仓库不能参赛（MCP 上线日作为分界） |
| 4 | **同一账号多项目只取 Star 最高的一个** | 别分散火力，集中打一个爆款 |
| 5 | **并列规则宽松** | 若 3 个项目并列第 1，则 3 个都拿第 1 名奖励，且不产生第 2/3 名 → **"并列第一"是现实的夺奖路径**，不必非要绝对第一 |

> 💡 **战术含义**：不必追求"压倒性第一"。**冲进并列第一集团（同为最高星数）就能拿满奖励**，这比"多 5 颗星"容易得多。

### 2.3 定榜与展示

- 排行榜只展示**前 100 名**；第 100 名若并列，则全部并列项目都进榜。
- 麦当劳**定时采集** Star 数据，写入活动主仓库的 `RANKING.md`。参赛者可自查。
- 排行榜展示 ≠ 通过资格审核。资格审核在评奖阶段进行。

### 5.2 五个候选方向（按推荐度排序）

---

#### 🥇 方向 A｜「麦麦资产管家」——积分 / 券 / 卡的"到期救援"与最优处置

**一句话**：你麦当劳账户里的积分和券，可能正在悄悄作废；它帮你把它们变成最大价值。

**为什么这是最优解**

- **钩子极锋利且反直觉**：竞品 `1024-M-CODE` 实测发现某用户「累计 1108.7 分、**已过期 923.2 分**」—— 这是几乎所有人都有、但从未有人告诉过的痛点。
- **传播力天然强**："我查了下我的麦当劳积分，发现已经过期了 900 分" 是标准的小红书爆款句式。
- **完全避开红海**：不碰点餐、不碰省钱、不碰营养。
- **工具覆盖广且冷门**：一次用上 8—10 个工具，其中抽奖、商城、商城订单是无人区。

**MCP 工具组合**

```
query-my-account            → 可用/累计/冻结/即将过期/已过期积分
query-my-coupons            → 我的券（含到期日）
available-coupons           → 麦麦省可领券
query-lottery-info          → 抽奖活动规则、奖品、消耗
draw-lottery                → 执行抽奖（写入类，需二次确认）
query-my-prizes             → 我的中奖记录
mall-points-products        → 积分商城商品（可兑换/可加钱）
mall-product-detail         → 商品详情（积分、有效期）
mall-create-order           → 积分兑换下单（写入类，需二次确认）
mall-order-list             → 商城订单历史
now-time-info               → 计算"还有几天到期"
```

**核心算法（可讲述的技术点）**

1. **到期倒计时排序**：把积分与券按过期日排成"急救队列"，输出「未来 7 天将要失效的资产清单」。
2. **抽奖 vs 兑换的期望值比较**：用 `query-lottery-info` 的奖品池和消耗规则估算单次抽奖期望值，与商城兑换的单位积分价值做对比，给出「该抽奖还是该兑换」的确定性建议。
3. **三档处置分类**：按积分把商品分为「够兑换 / 需攒 N 天 / 需加 ¥X」，并校验 `resourceEligible` 与 `status`。

**交付加分项**：一键生成「麦麦资产体检报告」分享图（HTML → 截图），直接可发朋友圈/小红书 → **这是换 Star 的引擎**。

**风险**：需要用户有积分数据，冷启动空。解法：内置样例数据可离线跑通（头部项目都这么做了）。

---

#### 🥈 方向 B｜「麦麦卡 ROI 精算师」——麦金卡 / 早餐卡值不值得买

**一句话**：不是"能不能省钱"，而是"这张卡在你的消费习惯下几天回本"。

**为什么好**：`麦金卡`、`早餐卡` 是麦当劳的高频付费产品，**用户在柜台前纠结是真实且普遍的**，但**全 GitHub 无人做**。且它天然需要"你的真实订单"→ 必须调 `order-list`，形成个性化壁垒。

**MCP 工具组合**：`order-list`（消费频率与客单价） + `calculate-price`（含卡价与折扣价对比） + `campaign-calendar`（活动叠加时机） + `query-my-coupons` + `mall-points-products` + `now-time-info`

**钩子**：「根据你过去 90 天的 27 笔订单，麦金卡在**第 12 天**回本，买。」

**可以叠加的传播层**：做成「麦当劳消费体质测试」——输入订单，输出你的"麦麦人格 + 该不该买卡"。娱乐化 = 转发率。

---

#### 🥉 方向 C｜「麦麦消费年报 Wrapped」——Spotify 年度报告式复盘

**一句话**：把 `order-list` + 营养数据 + 积分，生成一份可分享的"我的麦麦年报"。

**优点**：**传播性天花板最高**（Wrapped 类内容年年刷屏），直接兑换成 Star。
**缺点**：依赖用户历史订单量，数据薄的用户效果差；技术难度不高，容易被抄。
**工具**：`order-list` + `list-nutrition-foods` + `query-my-account` + `now-time-info` + `query-my-coupons`

#### 方向 D｜「麦麦派对策划师」——主题活动六层强依赖链

**核心公式：`Star = 触达 × 钩子强度 × 转化摩擦⁻¹`**

**② 产品侧为转化而设计（决定"看了会不会 star"）**

- **README 首屏三件套**：一句话价值 + 一张效果图 + 一个"惊艳数字"（如"省 53%"/"12 天回本"/"83% 积分被浪费"）。
- **零门槛试玩**：提供**无需 Token 的 dry-run**（内置样例数据），让访问者 30 秒内看到效果。**头部 11 个项目里已有 3 个用了这招。**
- **可视化 demo 页**：`docs/demo.html`，浏览器直接打开。
- **可分享物**：生成图片/海报 → 用户主动转发 → 新用户 → 新 Star（自增长闭环）。
- **持续 commit**：保持仓库"活着"的印象，GitHub 会给更多曝光。

规则原文明确禁止："通过或可能通过**机器人软件、脚本工具**，利用平台漏洞，抄袭、盗用他人项目，**恶意作弊、刷榜**、提交虚假参赛项目信息，**操纵 Star 数据或榜单**……"
